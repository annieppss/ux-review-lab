# AI 리뷰팀

일반 사용성 관점을 항상 포함하고, 사용자가 선택한 역할 1~3개의 관점으로 검토한다.

## 역할 선택

- 사용자가 역할을 지정하면 그대로 사용한다.
- 지정하지 않으면 UX/UI 디자이너, 기획자, 개발자를 사용한다.
- 일반 사용성 점검자는 사용자가 선택하는 역할 수에 포함하지 않는다.
- 선택 역할은 최대 3개로 제한한다. 4개 이상이면 목적에 가장 가까운 3개를 제안하거나 우선순위를 확인한다.
- 마케터, 특정 연령대 사용자, 접근성 검토자 등으로 자유롭게 교체할 수 있다.

## 기본 역할 관점

### 일반 사용성 점검자

- 처음 봐도 목적과 다음 행동을 이해하는가
- 낯선 용어, 상태, 되돌아가기 어려운 지점이 있는가

### UX/UI 디자이너

- 정보 위계와 시각적 흐름
- CTA, 선택·오류·로딩·완료 상태
- 일관성, 접근성, 반응형 위험

### 기획자

- 사용자의 목표와 화면 흐름
- 정책, 예외 상태, 성공·실패 조건
- 다음 단계와 이탈·복구 경로

### 개발자

- 구현 상태와 데이터 의존성
- 로딩, 오류, 중복 요청, 비동기 상태
- 컴포넌트와 API 계약의 모호함

## 종합

역할별 의견을 나열한 뒤 끝내지 않는다. 중복 항목을 합치고 다음 기준으로 정리한다.

- P0: 진행, 결제, 데이터 또는 신뢰를 막는 문제
- P1: 사용성 테스트 전에 수정할 문제
- P2: 시각적 완성도 단계에서 다듬을 문제
